Examples from the user's own merged PRs. When this file has entries, they outrank `examples.md` on tone, length, section names, and conventions such as title format.

No examples yet.

## How to add one

1. Pick a merged PR whose description a reviewer could approve from: the why is clear, the design is described, nothing in it turned out to be wrong.
2. Paste the title and body below, under a heading that names the kind of change (small fix, feature, refactor, migration step, and so on).
3. Remove anything confidential: customer names, internal hostnames, incident details that should not leave the team.
4. Add two to four bullets on what makes it good. These matter more than the example itself, because they tell the model which habits to copy.
5. If you improved the description before adding it, say what you changed and why. That is the most useful kind of example.

Three to five examples across different kinds of change are enough. More than that mostly adds tokens.
